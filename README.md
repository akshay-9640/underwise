# Underwise

Underwise reviews commercial property insurance submissions before an underwriter opens them. You give it a packet (the broker email, the application PDF, a locations schedule CSV and any loss runs report). It pulls out the key facts with a quote from the source for each one, runs five checks in plain code, and gives you an AI summary plus a draft follow-up email that asks the broker for whatever is missing or inconsistent.

The model reads documents. It never decides a rule, picks between sources, or invents a value: every value it reports must come with a quote that code finds on the stated page, or the value is not used.

All companies, people, addresses and rules in this repo are fictional. The output is readiness for human review, not a coverage, pricing or binding decision.

## How a packet is processed

1. **Read the files (code).** Email text, PDF text page by page, and the CSV. Unreadable PDFs (damaged, or scanned with no text) are listed as unreadable, never guessed at.
2. **Extract per source (model).** The model reads one document at a time and returns each field exactly as written, with a verbatim excerpt.
3. **Verify (code).** The excerpt must appear in that file, on the page it is attributed to, and the value must appear inside the excerpt. Anything else is rejected and shown as such.
4. **Normalize and merge (code).** `Ohio` and `OH` agree; `$10 million` and `$10,000,000` agree. When sources state different values, both are kept with their evidence and the field becomes a CONFLICT. No source is preferred.
5. **Check (code).** Five rules from [data/rules.json](data/rules.json) give PASS, FLAG or UNKNOWN.
6. **Summarize (model) and draft (code).** The summary only restates the JSON facts. The email draft is built in code, so every request in it maps to a failed check. Nothing is ever sent.
7. **Correct and rerun.** A reviewer can override any field with a reason. The original value and evidence stay visible, and the checks rerun on the corrected value.
8. **Ask about the packet.** Questions are answered only from the packet's own files and the check results. Every statement cites a source, and code verifies each quote.

## The checks

| Rule | PASS | FLAG | UNKNOWN |
|---|---|---|---|
| R1 Applicant and effective date | Both present and consistent | Either is absent | Invalid or conflicting |
| R2 Location count matches the schedule | Declared count equals CSV rows | Counts differ | A count is absent, conflicting, or the CSV is unreadable |
| R3 Total insured value within authority | TIV at or below $10,000,000 | Above $10,000,000 (senior referral) | Absent, conflicting or not a dollar amount |
| R4 Sprinkler protection | Explicit Yes | Explicit No | Absent, ambiguous or conflicting (silence is not No) |
| R5 Loss history | Loss runs attached and covering at least 3 years | Not attached, or fewer than 3 years | Attachment unreadable, type unclear, or years not stated |

The overall status is READY_FOR_REVIEW only when all five pass.

Fields have one of five states: KNOWN, MISSING (we looked and it is not there), CONFLICT, INVALID, and NOT_EXTRACTED (the model did not run). Keeping NOT_EXTRACTED separate from MISSING means a model outage never turns into a claim that something is absent.

## Accuracy

`underwise check-samples --runs 3 --report evals/accuracy.md` runs every packet through the live model three times and compares each field, rule and overall status with [tests/fixtures/expected.json](tests/fixtures/expected.json), which was written by hand from the rules, not from model output. It then reopens each file and confirms every quote is on the page its locator names.

Latest result with Claude Opus 5.5 through the Claude Code CLI: field checks 258/258, rules 60/60, overall status 12/12, excerpts on their stated page 195/195, about 10 to 25 seconds per packet. Full table in [evals/accuracy.md](evals/accuracy.md).

Four fictional packets is a small set. This shows the required cases work and stay consistent across runs; it does not measure accuracy on unseen document layouts.

## Run it

Needs Python 3.12 and [uv](https://docs.astral.sh/uv/).

```bash
uv sync
uv run underwise serve            # http://127.0.0.1:8000
```

With no model configured the app still runs the deterministic parts (CSV count, attachment inventory, checks on reviewer-entered values) and marks extraction as skipped. To enable the model, copy `.env.example` to `.env` and pick one option:

- **Claude Code CLI** (uses a Claude subscription, no API key): `UNDERWISE_LLM_PROVIDER=claude-code`, `UNDERWISE_LLM_MODEL=claude-opus-5-5`
- **Any OpenAI-compatible endpoint** (Ollama, OpenAI, Anthropic): `UNDERWISE_LLM_PROVIDER=openai` plus base URL, model and key

```bash
uv run --env-file .env underwise serve
uv run --env-file .env underwise run data/sample_submissions/P3-conflicts   # writes result.json and report.md
```

## Tests

```bash
uv run pytest -q
```

117 tests, fully offline. Model answers are replayed from a real recorded run (`tests/fixtures/recorded`), and hand-written fake answers cover the edge cases: invented quotes, values not inside their quote, model failures, prompt injection, unreadable files and upload validation. CI runs the same suite on every push.

## API

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/packets` | Upload files (and optionally pasted email text), process, return the result |
| GET | `/api/packets/{id}` | Stored result |
| POST | `/api/packets/{id}/process` | Reprocess, for example after a model outage |
| PUT / DELETE | `/api/packets/{id}/fields/{name}/override` | Set or clear a reviewer correction, then rerun the checks |
| POST | `/api/packets/{id}/ask` | Question about this packet, answered with verified citations |
| GET | `/api/packets/{id}/report` | Markdown report |
| GET | `/api/health` | Model configuration status |

## Layout

```
src/underwise/
  documents.py   reading email, PDF pages and the CSV; upload validation
  extract.py     per-source model reads, quote verification, normalizers, merging
  rules.py       R1 to R5 and the overall status
  narrative.py   AI summary and the code-built follow-up email draft
  ask.py         packet Q&A with verified citations
  pipeline.py    process, rerun, overrides
  llm.py         OpenAI-compatible and Claude Code CLI adapters
  app.py, web/   FastAPI app and the browser UI
data/            rules.json, field_specification.json, sample packets
scripts/         sample packet generator (dev only)
evals/           live accuracy report
```

## Limitations

- No OCR: a scanned PDF is reported as unreadable and the reviewer is asked for a text copy.
- One broker email and one locations CSV per packet.
- The rules and the $10M threshold are illustrative, not any insurer's guidelines.
- Uploaded packets are stored on local disk under `runs/`; there is no authentication, so run it locally.
